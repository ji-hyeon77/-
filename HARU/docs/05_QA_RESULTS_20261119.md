# HARU 기능 QA 보고서

2026년 11월 19일 기존 최종 배포본 v16을 점검했다. **새 자동 시험 35개 중 31개 통과 4개 실패**다. 실패는 응급 질문 라우팅 1건과 백업 복원 검증 3건이다. 배포 코드는 변경하지 않았으며 수정 완료로 보고하지 않는다.

## 대상과 근거

- 최종 앱 https://dialysis-os-haru.jovial-comet-6952.chatgpt.site
- 배포 버전은 Sites 메타데이터 v16으로 확인했다. 검증 전후 `core.js`와 `app.js` 바이트가 같다.
- 브라우저는 원격 데스크톱 Chrome 1363×936 CSS px이며, 표시 시간은 해당 브라우저 현지 시간이다. 실제 환자 0명 보호자 0명이다.
- 브라우저 초기 화면은 기록 0건 일정 미설정이었다. 전 과정에서 가상 데이터만 사용했다. 사용자 휴대전화의 기존 기록을 열거나 바꾸지 않았다.
- 배포 소스 사본을 Node v24.22.3에서 시험했다. Asia/Seoul과 UTC 각각 35개를 실행했고 둘 다 31 PASS 4 FAIL이다. **고유 시험은 35개이며 70개가 아니다.**
- `core.js`는 실제 배포 파일을 그대로 require했다. FAQ는 `app.js`에서 `normalize`, 고정 `testCases`, `findAnswer`를 그대로 추출해 VM에서 실행했다. A30 복원 병합은 핸들러 로직을 재구성한 코드 시험이며 브라우저 E2E가 아니다. 정상 복원은 UI에서도 별도로 수행했다.

## 복원 전후 데이터 보존

정상 파일 복원 전후에 앱의 백업 내려받기로 얻은 JSON을 비교했다. 11월 19일의 **기존 측정 5개 중 5개와 일자 객체 전체가 동일**하다. 기록일은 1일에서 2일로 늘었고 11월 18일의 혈당 105 1건이 추가됐다. 정기 일정 문자열과 날짜별 예외 문자열도 동일하다. 표본은 가상 데이터 단일 브라우저 1회이며 전체 사용자의 보존율이 아니다.
