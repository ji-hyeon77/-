# HARU | KPI·사용성 측정 계획

**작성:** 2026-11-19 · **상태:** 설계안 — 실사용 성과 수집 없음  
기존 앱의 로컬 저장 및 개인정보 제한을 바꾸지 않고 관찰 가능한 수동 테스트부터 시작한다.

## 1. North Star 후보

**의미 있는 기록-진료 준비 과업을 사용자가 스스로 완료하는 비율**

- 정의: 테스트 참여자가 가상 기록을 저장하고 지정 기간의 진료용 요약에서 해당 값을 오류 없이 찾은 과업 수 ÷ 해당 과업 시도 수.
- 왜 이 지표인가: HARU의 초기 가치는 매일 접속시키는 것이 아니라 **유효한 측정 맥락을 기록하고 필요한 순간 다시 찾는 것**에 있음.
- 데이터 소스: 동의받은 관찰 체크리스트. 현재 자동 수집 중인 지표가 아님.

## 2. KPI 정의 / 계측 가능성

| KPI | 계산식·측정 기준 | 첫 평가 목표(가설) | 지금 수치 |
|---|---|---|---|
| 핵심 과업 독립 완료율 | 도움 없이 '한 항목 저장→요약에서 확인' 완료 과업 / 시도 과업 | ≥80% | 미측정 |
| 단일 기록 소요시간 | 카드 진입부터 저장 확인까지, 성공 과업의 중앙값 | ≤60초 | 미측정 |
| 시점 이해 성공률 | 체중 전·후·가정의 서로 다른 의미를 올바르게 답한 수 / 유효 응답 수 | ≥90% | 미측정 |
| 다회 기록 보존율 | 테스트에서 기대한 별개 측정값 중 누락·덮어쓰기 없는 수 / 기대 값 수 | 100% | 사용자 평가 미측정 |
| 진료용 요약 정보 찾기 성공률 | 지정 날짜·값을 제대로 찾아낸 참여자 / 해당 과업 시도자 | ≥80% | 미측정 |
| 안전 안내 적절성 | 사전 정의한 위험 문구에서 응급 경로가 최우선으로 뜬 경우 / 시험 문구 수 | 모든 필수 문구 통과 | 배포본 새 시험 미실행 |
| 위험한 처방 출력 수 | 미리 정의한 금지 출력(투약량·제거수분량 결정 등) 건수 | 0건 | 임상 검증 미실행 |
| 저장 손실·충돌 | 재현 가능한 P0 기록 손실·다른 기록 덮어쓰기 수 | 0건 | 이전 QA 문서만 존재 |
| 7일 재사용률(후속) | 첫 기록 후 7일 이내 다시 유효 기록한 사용자 / 첫 기록 사용자 | 기준선 수집 후 설정 | 수집 불가 |

**지표 유의사항**
- 목표치가 실제 달성률이라는 뜻은 아니다.
- 5~7명의 소규모 사용성 시험에서 추정치의 불확실성이 크므로 정확한 분모·분자를 공개한다.
- '정상 상태' 또는 건강 개선 여부는 이 앱의 KPI로 추론하지 않는다.
- 단순 체류시간·기록 개수 확대는 과도한 기록 유도를 일으킬 수 있어 최상위 지표로 사용하지 않는다.

## 4. 후속 이벤트 설계 — 구현 전

| event_name | 의미 | 허용할 최소 속성(가명·비식별) |
|---|---|---|
| `record_start` | 유형별 기록 시작 | `task_id`, `record_type` |
| `record_save_success` | 가상 값 저장 완료 | `task_id`, `record_type` (수치 X) |
| `record_validation_error` | 검증 오류 발생 | `task_id`, `error_category` |
| `record_undo` | 되돌리기 사용 | `task_id` |
| `summary_open` | 진료용 요약 확인 | `task_id`, `range_type` |
| `summary_copy` | 요약 복사 선택 | `task_id` |
| `emergency_notice_shown` | 사전 정의 위험 표현 분기 | `test_case_id` (원문 X) |

위 이벤트는 **아직 HARU 최종 앱에 자동 계측으로 연결되지 않았다.** 민감한 건강 데이터·FAQ 질문 원문·기기 식별자 등을 외부 분석 도구로 전송하지 않는다. 실제 서비스 계측을 도입한다면 동의·법적 근거·보관기간·접근권한·삭제 절차를 먼저 설계한다.

## 5. PM 의사결정 규칙 (사전 가설)

- **과업 미완료가 많으면**: 새 기능 추가보다 입력 단계·저장 피드백·오류 안내를 우선 개선한다.
- **전후 체중을 혼동하면**: 시점 표기 및 정보 구조를 다시 설계하고 재평가한다.
- **요약 발견성이 낮으면**: 홈의 바로가기와 날짜별 탐색 구조를 개선한다.
- **임상 위험 오해가 발생하면**: 관련 안내·기능을 보류하고 의료진 검토 및 재시험을 우선한다.
- **자동 계측이 필요해지면**: 최소 수집·로컬 우선·동의 기반 운영을 검토한 다음 후속 버전으로 분리한다.

## 6. 보고할 때 반드시 붙일 문구

"본 KPI는 서비스 PM 관점의 사전 평가 설계이며, 실제 환자 사용성 시험·유지율·임상 효과를 측정한 결과가 아닙니다. 기존 자동 QA 47개 통과 기록은 **기능 테스트 결과**로 별도 관리하며 사용자 KPI 달성 근거로 사용하지 않습니다."
