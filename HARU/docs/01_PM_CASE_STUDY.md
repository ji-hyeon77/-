# HARU | 서비스 PM 사례 연구

> **상태:** 기존 배포 MVP를 보존한 서비스 기획·개선 사례 (2026-11-19 기준)  
> **체험:** https://dialysis-os-haru.jovial-comet-6952.chatgpt.site  
> **범위 주의:** 시연용, 가상 데이터 사용, 실제 환자 사용성 평가·임상 효과 검증 미수행

## 1. 문제 정의: 병원 밖 기록과 진료 준비 사이의 단절

약 3년의 임상 업무 중 혈액투석 환자가 병원 밖에서 측정한 체중·혈압·혈당·증상을 진료 시점에 재확인하는 과정을 관찰했다. **기획 가설:** 측정 시점(가정·투석 전·투석 후)과 시간을 보존하면서 필요한 항목만 짧게 입력하고, 진료 전에 사실 기반 요약으로 묶으면 기록 부담과 설명 부담을 줄일 수 있다. 이는 사용자 인터뷰로 검증된 문제가 아니라 **임상 경험에서 도출한 가설**이다.

**첫 사용자:** 스마트폰으로 직접 기록하거나 가족의 도움을 받을 수 있는 성인 혈액투석 환자. 당뇨병·모든 만성질환으로 대상을 넓히는 대신, 투석 일정과 전후 체중을 우선한다.

## 2. 제품 목표와 핵심 선택

**사용자 가치:** 빠른 단일 항목 기록 → 기록의 맥락 보존 → 진료용 요약.  
**제품 목표(가설):** 실제 사용자가 독립적으로 핵심 기록과 요약 확인을 완료할 수 있는가?

| 선택 | 제품 판단 | 현재 상태 |
|---|---|---|
| 체중·혈압·혈당·증상·메모 | 매일 모든 항목을 강제하지 않음 | MVP 화면·기록 흐름 존재 |
| 같은 날 복수 측정, 전·후·가정 체중 | 값의 시점과 개별 측정시간 보존 | 기존 검증 자료에 반영 |
| 정기 투석일+날짜별 예외 | 실제 병원 안내 일정과의 일치 | MVP 화면·기록 흐름 존재 |
| 기간별 진료용 요약 | 의료진에게 숫자와 메모를 보여줌 | MVP 화면 존재 |
| 로컬 저장·백업·복원·직전 되돌리기 | 저장 실패와 데이터 손실 위험 감소 | 기존 기능 및 QA 기록 존재 |
| 고정 FAQ·응급 연락 안내 | 개인 처방·진단으로 오인되지 않도록 제한 | MVP에 명시 |
| LLM, RAG, 개인별 AI 코칭 | 안전성·임상 검토 전 범위 확장 방지 | **미구현 / 향후 검토** |
| 로그인·동기화·보호자 계정 | 개인정보·운영 복잡도 증가 | **미구현** |

## 3. 사용자 흐름

1. **투석일**: 일정 확인 → 투석 전 체중 기록 → 투석 후 체중 추가 → 진료용 요약에서 각각의 시점과 시간을 확인한다.
2. **비투석일**: 혈압·혈당·증상 중 필요한 항목만 입력 → 다른 항목은 '미기록'으로 남긴다.
3. **진료 준비**: 기간 선택 → 날짜별 기록·메모 확인 → 복사 또는 인쇄 시도. 실제 기기 인쇄 완성도는 미검증이다.
4. **위험 문구 입력**: 안전 안내·119 연락 우선. 의학적 진단이나 안전 판정은 하지 않는다.

세부 테스트 시나리오: [사용자 시나리오](03_USER_SCENARIOS.md).

## 4. 실행 범위와 증거 구분

- **기획·임상 맥락:** 문제 가설 정의, 우선순위 설정, 의료적 안전 경계, 검증 기준 정리.
- **구현 지원:** 기존 프런트엔드를 AI 도구의 도움으로 개선하고 주요 기능 테스트·문서화를 수행한 사례. 독자적으로 전체 원본 코드를 처음부터 작성했다고 주장하지 않는다.
- **이전 검증 기록:** 2026-11-17 포트폴리오에 고유 자동 시험 47개(데이터·저장 로직 30, HTML/이벤트 17)가 통과했다고 기록되어 있다. Asia/Seoul, UTC 각각 반복 실행했으나 **94개 고유 기능 시험이 아님**.
- **이 답변에서 새로 수행한 시험:** 없음. 이전 문서의 시험 기록을 재현하거나, 배포 중인 앱을 실기기에서 새로 조작한 것으로 표현하지 않는다.
- **미수행:** 실제 환자·보호자 사용성 평가, 의료진 콘텐츠 전체 검토, 임상 효과 검증, 실제 휴대전화 알림·인쇄 신뢰성 검증.

## 5. 평가 계획과 개선 가설

| 가설 | 검증 방법 | 목표(미달성/가설) |
|---|---|---|
| 단일 항목 기록이 쉽다 | 실제 참여자에 의한 '혈압 1회 기록' 독립 수행 | 독립 완료율 ≥80%, 중앙값 ≤60초 |
| 전후 체중을 이해할 수 있다 | 투석 전·후·가정 기록을 요약에서 정확히 구분하는지 질문 | 맥락 식별 성공률 ≥90% |
| 진료 준비에 유용하다 | 기존 기록 중 요청한 날짜·값을 찾아 보여주는 과업 | 독립 완료율 ≥80% |
| 안전 경계를 이해한다 | 응급 문구 및 '미기록≠무증상' 해석 확인 | 위해 가능 오해 0건을 목표로 하되 표본 규모와 함께 보고 |

모두 **평가 설계상의 목표치**이며 사용자 성과나 달성률이 아니다. KPI 정의와 데이터 취급 조건: [측정 계획](04_KPI_MEASUREMENT_PLAN.md).

## 6. PM 관점에서의 학습

**핵심 결정은 'AI 기능을 많이 넣기'보다 신뢰할 수 있는 기록 MVP에 집중한 것**이다. 의료 AI의 가치는 모델 연결 자체가 아니라 현장에서 필요한 과업·입력 맥락·안전 경계가 정의된 후에 검증할 수 있다. 향후에는 ① 실기기 회귀 ② 사용성 평가 ③ 의료진 문구 검토 ④ 안전한 AI 기능의 별도 타당성 검증 순서로 진행한다.
