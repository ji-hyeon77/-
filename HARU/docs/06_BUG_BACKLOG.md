# HARU 재현 결함과 개선 우선순위

2026년 11월 19일. 모두 OPEN이며 배포 수정은 하지 않았다. S1은 응급 경로 누락 위험 S2는 데이터 신뢰 훼손 위험으로 구분한다. 릴리스 우선순위 P0는 심각도와 별개로 다음 배포 전에 고칠 항목을 뜻한다.

## BUG-01 응급 표현이 일반 수분 FAQ로 분류됨

**S1 매우 높음 P0**. 배포 UI와 다운로드한 소스의 A35에서 재현했다.

1. 도우미로 들어간다.
2. 가상 질문 `오늘 물 얼마나 마셔도 돼요? 갑자기 말이 어눌하고 한쪽 팔에 힘이 안 들어가요`를 보낸다.
3. 실제로 F-01의 수분 목표 확인과 국물 과일 얼음 기록 안내가 나온다. 해당 답변에는 응급 우선 도움 요청이 없다. 화면 옆의 상시 안내는 흉통 호흡곤란 의식 저하를 열거한다.

기대 결과는 위험 표현이 포함된 경우 수분 FAQ보다 응급 도움 경로를 먼저 제시하는 것이다. `HaruCore.urgent`에 말 어눌함과 편측 힘 빠짐 계열의 표현이 없고 FAQ 키워드가 매칭되어 일반 답변으로 진행한다. 일부 표현을 추가해도 모든 응급 상태를 인식할 수 있다는 주장은 하지 않는다.

수정안은 의료진 검토로 필수 위험 표현과 비슷한 일상 표현을 선정하고 일반 FAQ 앞에서 보수적으로 라우팅하는 것이다. 단독 표현 혼합 질문 띄어쓰기 변형과 비위험 대조군을 함께 회귀 시험한다. AI나 개인 위험도 판정으로 기능 범위를 넓히지 않는다.

## BUG-02 음수 혈당이 백업 검증을 통과함

**S2 높음 P0**. A31 코드 경계 시험에서 재현했다. 브라우저의 비정상 파일 업로드는 수행하지 않았다.

1. `core.js`의 `validateRecords`에 `[{date:'2026-11-17',glucoseEntries:[{id:'bad',time:'08:00',value:-10}]}]`를 전달한다.
2. 예외가 발생해야 하지만 반환된다.
3. 복원 핸들러는 이 함수로 검증한 후 없는 날짜를 추가한다. 정상 입력 UI의 `measurement` 함수와 복원 경로의 수치 검증이 다르다.

수정안은 복원 입력에도 측정 종류별 유효성 검증을 적용하는 것이다. 해당 날짜가 현재 기록과 중복되면 추가되지 않는 현행 보존 정책은 유지한다. 빈 문자열 null 음수 소수 비숫자 범위 밖 값을 함께 검증한다.

## BUG-03 역전 혈압이 백업 검증을 통과함

**S2 높음 P0**. A32 코드 경계 시험에서 재현했다.

`validateRecords([{date:'2026-11-16',bpEntries:[{id:'bad',time:'08:00',systolic:70,diastolic:120}]}])`가 거부되지 않는다. 신규 입력 UI는 같은 관계를 거부한다. 음수 혈당과 같은 복원 경로의 검증 누락이며 별도 발생 횟수가 확인된 것은 아니다.

수정 후에는 한 쌍 누락 수치 순서 정수 조건이 모두 신규 입력 규칙과 일치해야 한다. 기존 보존 데이터가 잘못되어도 자동 교정하거나 삭제하지 않고 원본을 보존하며 확인을 요구한다.

## BUG-04 미래 날짜가 백업 검증을 통과함

**S2 높음 P0**. A33 코드 경계 시험에서 재현했다.

`validateRecords([{date:'2099-01-01',glucose:100}])`가 거부되지 않는다. 신규 입력은 오늘 이후 날짜를 막는다. 일정은 미래 날짜가 가능하지만 건강 측정 기록은 별개의 규칙이다.

수정안은 가져오기 전 기록일과 측정시각을 검증하되 시간대 이동과 과거 기록의 미기록 시간을 고려하는 것이다. 원래 시간이 없는 기존 자료에 시간을 임의로 넣지 않는다. 미래 자료의 처리 정책을 안내한 후 일괄 원자적 복원 또는 검증된 항목만 복원 중 하나를 명시적으로 설계한다.

## 수정 후 인수 기준

1. BUG-01 혼합 질문이 일반 FAQ보다 응급 도움 안내를 우선한다.
2. BUG-02~04 자료를 가져오려 할 때 오류와 이유를 보여주고 현재 기록 일정 예외는 불변이다.
3. 정상 백업은 기존 날짜 전체 유지와 새 날짜 추가 정책을 그대로 따른다.
4. 기존 형식 자료의 값과 미기록 시간은 보존한다.
5. 실패 회귀 4건과 정상 코드 31건을 재실행하고 모바일 주요 과업도 확인한 뒤 배포 여부를 검토한다.

자동 시험 35개만 통과해도 임상 안전이나 실제 사용성을 입증한 것은 아니다. 배포 승인 전에는 최종 앱 QR main을 변경하지 않는다.
