## 1. 문제 정의 (Why)

르올·오넬로이 자사몰의 **실구매 후기에는 '부모님 선물', '무게', '세탁'에 대한 고민이 반복해서 등장**합니다. 그런데 정작 구매를 결정하는 주문 화면에는 그 답이 없습니다.

- **세탁기 용량 기준이 주문 화면에 없음** — "20kg 이상 세탁기에서 세탁망 사용 권장" 같은 안내가 상품 선택 화면이 아니라 자주묻는질문(FAQ) 게시판에만 있음
- **무게를 비교할 표가 없음** — "어르신이 덮기에 얼마나 가벼운지"를 제품 간에 한눈에 비교할 수 없음
- **선물 옵션이 주문 단계에 없음** — 선물 포장·메시지 카드 선택지가 따로 없어, 실속형 '1+1' 구성 중 무엇을 선물용으로 골라야 할지 고객이 직접 판단해야 함

즉, 고객이 **구매 직전에 확인하고 싶은 정보가 흩어져 있어 비교하다 이탈하는 구간**이 생깁니다. 이 MVP는 그 지점에서 "고르는 수고"를 대신 해주고, **구매 결정과 결제는 기존 자사몰로 넘기는 것**을 목표로 기획·구현했습니다.

---

## 2. 사용자 플로우 (4 Steps)

| 단계 | 화면에서 묻는 것 | 선택지 | 결과에 반영되는 기준 |
| --- | --- | --- | --- |
| **① 수면 온도 스타일** | 추위를 많이 타는지, 열이 많고 땀이 나는지 | 추위 많음 / 열·땀 많음 / 사계절 무난 | 보온 중심 vs 가볍고 통기성 좋은 소재 |
| **② 세탁기 용량** | 부모님 댁 세탁기가 이불을 감당하는지 | 20kg 이상 / 15kg 이하·이불 빨래 부담 / 모름 | 이불 본체 세탁 가능 vs 커버 분리 세탁 구성 |
| **③ 먼지·알러지·무게 민감도** | 피부·호흡기가 예민한지, 무거운 이불이 답답한지 | 민감함 / 무거운 이불 싫어함 / 특이 없음 | 알러지케어 소재 vs 경량 충전재 |
| **④ 선물 구성** | 어떤 구성으로 선물할지 | 1+1(부모님 댁 + 내 집) / 단품 + 선물 메시지 카드 / 커버 세트 포함 | 구성·가격(채당 단가)·포장 |

**→ 결과 화면**

- 4문항을 가중치 점수로 합산해 3개 상품 중 **가장 잘 맞는 1개를 추천** (르올 구스이불 · 르올 알러지프리 이불 · 오넬로이 헬렌 이불세트)
- 왜 이 상품인지 **3줄 추천 근거**를 고객의 답변 언어로 제시
- 선택한 구성에 따른 **금액과 채당 단가** 계산
- 입력한 **선물 메시지를 카드 형태로 미리보기**
- **자사몰 상품 페이지로 바로 이동**, 차선책 상품도 함께 제안

---

## 3. MVP 범위 (In / Out of Scope)

### 포함 (In)

- **4문항 맞춤 매칭 로직** — 답변별 가중치 점수 합산으로 최적 상품 1개 산출
- **제품별 3줄 추천 근거** — 세탁·민감도·구성 답변을 그대로 문장으로 되돌려 주는 개인화 카피
- **선물 메시지 미리보기** — 입력한 메시지를 결과 카드에 그대로 렌더링
- **자사몰 상품 이동** — 르올·오넬로이 실제 상품 페이지로 연결
- **인페이지 퍼널 이벤트 로그** — `session_start` → `step_view`(1~4) → `recommend_complete` → `product_click`을 발생 시점과 함께 기록

### 제외 (Out)

| 뺀 기능 | 뺀 이유 |
| --- | --- |
| 회원가입 / 로그인 | 로그인 장벽이 1차 가설(추천이 클릭·구매를 늘리는가)을 흐림 |
| 자체 결제 시스템 | 결제·배송·반품을 새로 만드는 비용 대비 검증 속도 손실 — 자사몰 결제로 연결해 **1차 가설 검증 속도를 극대화** |
| 재고·배송 조회, 리뷰 작성, 찜하기 | 구매 결정에는 영향이 적고, 검증 후 확장 과제로 이관 |

## 4. 검증 지표 & 중단 기준

**퍼널 지표** (프로토타입에 기록되는 이벤트 기준)

| 지표 | 계산 | 보는 것 |
| --- | --- | --- |
| 시작률 | `session_start` 대비 1문항 노출 | 유입 대비 추천기 진입 |
| 완료율 | `recommend_complete` / `session_start` | 4문항 중 어디서 끊기는지(이탈 스텝) |
| 상품 클릭률(CTR) | `product_click` / `recommend_complete` | 추천이 실제 '관심'으로 이어지는지 |
| 구매 전환율(CVR) | 자사몰 주문 / `product_click` | 추천이 매출로 이어지는지(자사몰 유입 경로로 연결) |

**판단 기준**

- **확대**: 기존 상품 상세페이지 대비 구매 전환율이 개선되고, 할인·구성 조정 후에도 **마진이 확보**되는 경우 → 상세페이지 내 상설 모듈로 편입
- **중단**: 기존 상세페이지 대비 전환 개선이 확인되지 않거나 마진 확보가 안 되는 경우 → **기능 종료**(안내표 개선만 남기고 추천 로직은 접음)
- 기준선(baseline)은 기존 상세페이지의 CVR을 먼저 측정해 고정한 뒤 비교합니다.

프로토타입에서는 이벤트가 브라우저 콘솔과 **화면 하단 로그 패널**에 함께 남아, 어느 스텝에서 퍼널이 끊기는지 즉시 확인할 수 있습니다.

## 5. 구현

- **단일 파일** (HTML/CSS/JS) — 외부 라이브러리·CDN 의존 없이 오프라인에서도 그대로 실행
- **모바일 우선** — 390px 기준 설계, 최대 430px 프레임. 데스크톱에서는 중앙 정렬된 모바일 프레임으로 표시
- 4문항 진행률 표시, 이전 단계 이동, 선택 상태(`aria-pressed`)·안내 메시지(`aria-live`) 등 기본 접근성 반영
